# M1-2 岩心柱前景掩膜算法模块前端联调说明

## 1. 文档目的

本文档面向前端开发工程师和软件集成工程师，用于说明当前 M1-2 岩心柱前景掩膜算法模块已经具备的功能、API 调用方式、输入输出数据结构，以及前端可以实现的交互操作。

前端不需要直接调用 Python 算法函数，也不需要理解模型训练参数。前端只需要通过 HTTP API 将岩心图像提交给后端，后端完成前景掩膜提取后返回任务状态、输出文件路径、质量指标和可视化预览结果。用户如果发现掩膜中存在误检区域，前端可以通过框选、多边形或画笔工具把需要删除的区域反馈给后端，后端会同步修改最终二值掩膜。

## 2. 模块定位

M1-2 模块是岩心智能编录软件中前处理阶段的核心算法模块，主要负责从岩心箱、岩心柱或岩心图像中识别岩心实体区域，生成岩心前景掩膜。

该模块当前服务于以下业务目标：

- 从原始岩心图像中提取岩心实体前景区域；
- 过滤木箱、卡槽、标尺、标签纸、阴影、空洞背景等非岩心区域；
- 输出可供前端叠加展示的预览图；
- 输出可供后续 M1-3 岩心柱分割、深度标定和 M2 属性识别使用的二值掩膜；
- 支持用户在前端人工修正模型误检区域，并将修正结果同步回后端。

## 3. 当前后端能力概览

当前模块以 FastAPI 服务形式对外提供能力。

已支持的能力包括：

- 系统状态查询；
- 可用模型列表查询；
- 基于后端可访问文件路径创建前景掩膜任务；
- 通过上传文件创建前景掩膜任务；
- 任务状态轮询；
- 结果文件路径返回；
- 掩膜文件下载；
- 人工编辑掩膜，删除用户选择的误检区域；
- 重新生成编辑后的 `mask.png`、`mask.tif`、`overlay.png`、`contours.json` 和 `metadata.json`。

当前人工编辑能力主要支持“删除误检前景区域”。如果后续需要“补画漏检区域”，可以在现有接口基础上扩展 `operation: "add"`。

## 4. 服务启动与接口文档

在项目根目录启动服务：

```powershell
python -m uvicorn api.main:app --host 0.0.0.0 --port 8000
```

也可以双击或执行：

```powershell
run_api_server.bat
```

服务启动后，浏览器打开：

```text
http://127.0.0.1:8000/docs
```

这里可以查看 FastAPI 自动生成的 OpenAPI 文档，并直接调试接口。

默认服务地址：

```text
http://127.0.0.1:8000
```

## 5. 前端推荐调用流程

前端推荐按以下流程对接：

```text
1. 查询服务状态
2. 创建前景掩膜任务
3. 获取 task_id
4. 轮询任务状态
5. 任务成功后读取 output_files
6. 前端展示 overlay.png、mask.png 或 contours.json
7. 用户发现误检区域后，在前端框选/圈选/涂抹
8. 调用 mask-edits 接口提交用户选择区域
9. 后端刷新最终掩膜文件
10. 前端重新加载最新结果
```

| 功能 | 方法 | 路径 |

| 上传文件并创建任务 | `POST` | `/api/m1/foreground-mask/upload` |

## 7. 输入数据说明

### 7.1 支持的图像来源

当前支持两种输入方式：

- 后端本机或服务器可访问的图像路径；
- 前端通过 multipart/form-data 上传图像文件。

路径方式更适合桌面软件、局域网部署或后端已经能访问项目数据目录的场景。上传方式更适合 Web 前端直接提交本地文件。

### 7.2 支持的图像格式

模块设计上支持常见岩心图像格式：

- `.jpg`
- `.jpeg`
- `.png`
- `.tif`
- `.tiff`

当前默认 `image_pattern` 是 `*.tif`。如果输入目录中是 JPG 或 PNG，前端需要在请求中显式指定 `image_pattern`，例如 `*.jpg`。

### 7.3 单图输入

如果 `input_path` 是文件路径，后端只处理这一张图像。

示例：

```json
{
  "input_path": "D:/data/core_box_001.tif",
  "model_profile": "default",
  "threshold": 0.5,
  "enable_postprocess": true,
  "output_preview": true
}
```

### 7.4 目录输入

如果 `input_path` 是目录路径，后端会按 `image_pattern` 查找图像。

示例：

```json
{
  "input_path": "D:/data/core_images",
  "image_pattern": "*.tif",
  "recursive": false,
  "model_profile": "default",
  "threshold": 0.5,
  "enable_postprocess": true,
  "output_preview": true
}
```

字段说明：

| 字段 | 类型 | 必填 | 默认值 | 说明 |
| --- | --- | --- | --- | --- |
| `input_path` | string | 是 | 无 | 后端可访问的图像文件路径或目录路径 |
| `output_dir` | string | 否 | `api_runtime/outputs/{task_id}` | 结果输出目录 |
| `image_pattern` | string | 否 | `*.tif` | 当 `input_path` 是目录时使用的文件匹配规则 |
| `recursive` | boolean | 否 | `false` | 是否递归扫描子目录 |
| `model_profile` | string | 否 | `default` | 模型配置名称，正式使用一般保持默认 |
| `model_package` | string | 否 | `null` | 显式指定模型包目录，通常前端不需要传 |
| `threshold` | number | 否 | 模型包配置 | 前景概率阈值，范围 0 到 1 |
| `enable_postprocess` | boolean | 否 | 模型包配置 | 是否启用岩心专用后处理 |
| `output_preview` | boolean | 否 | `true` | 是否输出 `overlay.png` |

前端一般只需要关心 `input_path`、`image_pattern`、`threshold`、`enable_postprocess` 和 `output_preview`。

## 8. 创建前景掩膜任务

推荐接口：

```text
POST /api/preprocessing/foreground-mask
```

请求体：

```json
{
  "input_path": "examples/input",
  "image_pattern": "*.tif",
  "model_profile": "default",
  "threshold": 0.5,
  "enable_postprocess": true,
  "output_preview": true
}
```

响应示例：

```json
{
  "task_id": "8fb5e33fbc9d4d4f9a9a9bbaf64f4c71",
  "status": "pending",
  "status_url": "/api/m1/foreground-mask/jobs/8fb5e33fbc9d4d4f9a9a9bbaf64f4c71"
}
```

说明：

- 该接口会立即返回 `task_id`；
- 后端会在后台执行模型推理；
- 前端不要等待该接口直接返回掩膜结果；
- 前端应使用 `task_id` 轮询任务状态。

## 9. 查询任务状态

推荐接口：

```text
GET /api/preprocessing/status/{task_id}
```

响应示例：

```json
{
  "task_id": "8fb5e33fbc9d4d4f9a9a9bbaf64f4c71",
  "status": "succeeded",
  "message": "foreground mask extraction completed",
  "input_paths": [
    "examples/input/sample.tif"
  ],
  "output_dir": "api_runtime/outputs/8fb5e33fbc9d4d4f9a9a9bbaf64f4c71",
  "output_files": {
    "mask_png": "api_runtime/outputs/8fb5e33fbc9d4d4f9a9a9bbaf64f4c71/mask.png",
    "mask_tif": "api_runtime/outputs/8fb5e33fbc9d4d4f9a9a9bbaf64f4c71/mask.tif",
    "probability_tif": "api_runtime/outputs/8fb5e33fbc9d4d4f9a9a9bbaf64f4c71/probability.tif",
    "overlay_png": "api_runtime/outputs/8fb5e33fbc9d4d4f9a9a9bbaf64f4c71/overlay.png",
    "contours_json": "api_runtime/outputs/8fb5e33fbc9d4d4f9a9a9bbaf64f4c71/contours.json",
    "metadata_json": "api_runtime/outputs/8fb5e33fbc9d4d4f9a9a9bbaf64f4c71/metadata.json"
  },
  "metrics": {
    "foreground_area_ratio": 0.32,
    "component_count": 8,
    "elapsed_seconds": 2.31
  },
  "warnings": [],
  "error": null,
  "created_at": "2026-06-13T10:00:00+00:00",
  "updated_at": "2026-06-13T10:00:03+00:00"
}
```

### 9.1 任务状态枚举

| 状态 | 含义 | 前端建议 |
| --- | --- | --- |
| `pending` | 任务已创建，等待执行 | 显示等待状态 |
| `running` | 正在执行模型推理 | 显示进度或加载动画 |
| `succeeded` | 执行成功 | 加载输出文件并展示 |
| `failed` | 执行失败 | 展示 `error` 字段并允许重试 |

### 9.2 前端轮询建议

建议前端每 500 ms 到 2000 ms 轮询一次任务状态。图像较大、GPU 不可用或批量目录输入时，任务耗时会增加。

## 10. 输出文件说明

单图任务默认输出目录：

```text
api_runtime/outputs/{task_id}/
  mask.png
  mask.tif
  probability.tif
  overlay.png
  contours.json
  metadata.json
```

### 10.1 mask.png

用途：前端快速预览二值掩膜。

特点：

- PNG 格式；
- 背景为 0；
- 前景为 255；
- 适合在前端作为透明图层、Canvas 图层或调试图显示；
- 不建议作为后续算法的正式输入，正式算法应优先使用 `mask.tif`。

### 10.2 mask.tif

用途：后续 M1-3、M2 等算法模块的正式掩膜输入。

特点：

- 与原图同尺寸；
- 背景为 0；
- 前景为 255；
- 如果原图包含地理或空间参考信息，后端会尽量保留；
- 用户人工编辑后，该文件会被同步更新。

### 10.3 probability.tif

用途：模型原始前景概率图。

特点：

- 表示模型对每个像素属于岩心前景的置信程度；
- 当前保存为 0 到 255 的灰度图；
- 主要用于模型质量分析、阈值调试和错误排查；
- 用户人工编辑掩膜时，该文件不会改变，因为它代表模型原始输出。

### 10.4 overlay.png

用途：前端展示原图与掩膜的叠加效果。

特点：

- 原图上以半透明颜色叠加前景区域；
- 适合给用户快速判断识别结果；
- 用户人工编辑掩膜后，如果 `output_preview` 为 `true`，该文件会被重新生成。

### 10.5 contours.json

用途：前端绘制轮廓、包围盒、连通域信息。

示例结构：

```json
{
  "image_width": 4096,
  "image_height": 2048,
  "component_count": 2,
  "components": [
    {
      "component_id": 1,
      "area": 123456,
      "bbox": [100, 220, 1600, 420],
      "centroid": [850.2, 310.5],
      "contour": [[100.0, 220.5], [101.0, 220.5]]
    }
  ]
}
```

字段说明：

| 字段 | 说明 |
| --- | --- |
| `image_width` | 图像宽度，单位像素 |
| `image_height` | 图像高度，单位像素 |
| `component_count` | 连通域数量 |
| `components` | 连通域列表 |
| `component_id` | 连通域编号 |
| `area` | 连通域面积，单位像素 |
| `bbox` | 包围盒 `[x_min, y_min, x_max, y_max]` |
| `centroid` | 中心点 `[x, y]` |
| `contour` | 轮廓点列表，点格式为 `[x, y]` |

### 10.6 metadata.json

用途：记录模型、参数、质量指标和人工编辑历史。

示例结构：

```json
{
  "module": "M1-2 foreground mask",
  "model_name": "CoreMaskUNet",
  "model_version": "v1.0.0",
  "input_path": "examples/input/sample.tif",
  "threshold": 0.5,
  "postprocess": true,
  "image_width": 512,
  "image_height": 512,
  "foreground_area_ratio": 0.32,
  "component_count": 8,
  "warnings": [],
  "elapsed_seconds": 2.31,
  "manual_edit_applied": true,
  "manual_edit_history": [
    {
      "operation": "remove",
      "region_count": 1,
      "selected_pixel_count": 6900,
      "removed_pixel_count": 1556,
      "edited_at": "2026-06-13T18:03:04.566900+00:00"
    }
  ]
}
```

前端可以使用 `foreground_area_ratio`、`component_count` 和 `warnings` 做质量提示。

## 11. 人工编辑掩膜交互

### 11.1 业务场景

模型初次提取前景后，可能出现以下情况：

- 木箱纹理被误识别为岩心；
- 标签纸或标尺被识别为前景；
- 阴影、反光或污渍被识别为岩心；
- 某些不需要进入后续算法的碎屑被识别为前景。

此时前端可以让用户通过交互工具选择这些区域，并调用后端接口删除对应掩膜。

### 11.2 支持的前端工具

当前后端支持三类选择区域：

| 工具 | region type | 适用场景 |
| --- | --- | --- |
| 矩形框选 | `rectangle` | 快速删除规则矩形误检区域 |
| 多边形圈选 | `polygon` | 删除不规则区域 |
| 画笔涂抹 | `brush` | 细粒度修正局部误检 |

当前支持的操作：

| 操作 | operation | 含义 |
| --- | --- | --- |
| 删除 | `remove` | 从当前前景掩膜中删除所选区域 |

### 11.3 人工编辑接口

推荐接口：

```text
POST /api/preprocessing/foreground-mask/{task_id}/mask-edits
```

模块级接口：

```text
POST /api/m1/foreground-mask/jobs/{task_id}/mask-edits
```

请求体通用结构：

```json
{
  "operation": "remove",
  "regions": [],
  "display_width": 1024,
  "display_height": 512,
  "output_preview": true
}
```

字段说明：

| 字段 | 类型 | 必填 | 默认值 | 说明 |
| --- | --- | --- | --- | --- |
| `operation` | string | 否 | `remove` | 当前仅支持删除前景 |
| `regions` | array | 是 | 无 | 用户选择区域列表 |
| `display_width` | number | 否 | `null` | 前端预览画布宽度 |
| `display_height` | number | 否 | `null` | 前端预览画布高度 |
| `result_key_prefix` | string | 否 | `""` | 批量任务中指定某张图的结果前缀 |
| `output_preview` | boolean | 否 | `true` | 是否重新生成 `overlay.png` |

### 11.4 坐标系统约定

默认情况下，后端认为前端传入的是原始图像像素坐标。

坐标原点：

```text
左上角为 (0, 0)
x 向右增大
y 向下增大
```

如果前端是在缩放后的预览画布上操作，例如原图是 `4096 x 2048`，前端显示为 `1024 x 512`，则前端应传：

```json
{
  "display_width": 1024,
  "display_height": 512
}
```

后端会自动将前端坐标映射回原始图像坐标。

### 11.5 矩形框选示例

```json
{
  "operation": "remove",
  "regions": [
    {
      "type": "rectangle",
      "bbox": [120, 80, 260, 180]
    }
  ],
  "output_preview": true
}
```

`bbox` 含义：

```text
[x1, y1, x2, y2]
```

前端不需要保证 `x1 < x2` 或 `y1 < y2`，后端会自动处理。

### 11.6 多边形圈选示例

```json
{
  "operation": "remove",
  "regions": [
    {
      "type": "polygon",
      "points": [
        [300, 120],
        [430, 126],
        [420, 230],
        [290, 220]
      ]
    }
  ]
}
```

说明：

- `points` 至少需要 3 个点；
- 点顺序建议按用户绘制顺序传入；
- 后端会将多边形内部区域作为待删除区域。

### 11.7 画笔涂抹示例

```json
{
  "operation": "remove",
  "regions": [
    {
      "type": "brush",
      "radius": 12,
      "points": [
        [520, 200],
        [540, 210],
        [565, 220]
      ]
    }
  ]
}
```

说明：

- `radius` 是画笔半径，单位为像素；
- `points` 是画笔移动路径采样点；
- 后端会沿路径生成连续涂抹区域。

### 11.8 混合编辑示例

一次请求可以包含多个区域，也可以混合不同工具：

```json
{
  "operation": "remove",
  "display_width": 1024,
  "display_height": 512,
  "regions": [
    {
      "type": "rectangle",
      "bbox": [100, 50, 240, 180]
    },
    {
      "type": "polygon",
      "points": [[300, 120], [430, 126], [420, 230], [290, 220]]
    },
    {
      "type": "brush",
      "radius": 10,
      "points": [[520, 200], [540, 210], [565, 220]]
    }
  ]
}
```

### 11.9 人工编辑响应

响应示例：

```json
{
  "task_id": "8fb5e33fbc9d4d4f9a9a9bbaf64f4c71",
  "status": "succeeded",

    "contours_json": "api_runtime/outputs/8fb5e33fbc9d4d4f9a9a9bbaf64f4c71/contours.json",

    "component_count": 6,
    "selected_pixel_count": 6900,
    "removed_pixel_count": 1556,

  },
```

- `mask_tif`

## 12. 批量任务说明

如果 `input_path` 是目录，并且匹配到多张图，后端会生成批量任务结果。

批量任务的 `output_files` key 会带上图像名前缀，例如：

```json
{
  "sample1.mask_png": "api_runtime/outputs/task/sample1/mask.png",
  "sample1.mask_tif": "api_runtime/outputs/task/sample1/mask.tif",
  "sample2.mask_png": "api_runtime/outputs/task/sample2/mask.png",
  "sample2.mask_tif": "api_runtime/outputs/task/sample2/mask.tif",
  "results_json": "api_runtime/outputs/task/results.json"
}
```

如果前端要编辑批量任务中的某一张图，需要传 `result_key_prefix`：

```json
{
  "operation": "remove",
  "result_key_prefix": "sample1.",
  "regions": [
    {
      "type": "rectangle",
      "bbox": [120, 80, 260, 180]
    }
  ]
}
```

单图任务不需要传 `result_key_prefix`。

## 13. 上传文件接口

如果前端希望直接上传图像，可以使用：

```text
POST /api/m1/foreground-mask/upload
```

请求类型：

```text
multipart/form-data
```

主要字段：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `file` | file | 是 | 要识别的图像文件 |
| `model_profile` | string | 否 | 默认 `default` |
| `threshold` | number | 否 | 前景阈值 |
| `enable_postprocess` | boolean | 否 | 是否启用后处理 |
| `output_preview` | boolean | 否 | 是否生成叠加预览 |

响应仍然是任务创建响应，前端继续用 `task_id` 轮询任务状态。

## 14. 前端展示建议

### 14.1 基础结果展示

建议前端至少展示：

- 原始图像；
- `overlay.png` 作为模型结果快速预览；
- `mask.png` 作为调试或半透明叠加图层；
- `contours.json` 绘制轮廓和包围盒；
- `metadata.json` 中的质量指标。

### 14.2 推荐交互布局

推荐前端界面包含：

- 原图/叠加图切换；
- 掩膜透明度调节；
- 轮廓显示开关；
- 包围盒显示开关；
- 框选删除工具；
- 多边形删除工具；
- 画笔删除工具；
- 撤销提示或重新推理按钮；
- 当前前景面积比例、连通域数量、质量警告展示。

当前后端没有提供“撤销编辑”接口。若前端需要撤销，可以先在前端保留用户操作栈，或者重新运行一次推理任务恢复初始模型结果。

### 14.3 缓存刷新

人工编辑后，文件路径通常不变，但文件内容已经更新。前端重新加载图片时建议增加缓存破坏参数：

```text
overlay.png?t=当前时间戳
mask.png?t=当前时间戳
```

否则浏览器可能继续显示旧图。

## 15. 错误处理建议

常见 HTTP 状态：

| 状态码 | 场景 | 前端建议 |
| --- | --- | --- |
| `202` | 成功创建异步任务 | 保存 `task_id` 并开始轮询 |
| `200` | 查询或编辑成功 | 正常展示结果 |
| `400` | 请求参数错误或缺少可编辑掩膜文件 | 提示用户检查输入 |
| `404` | `task_id` 不存在 | 提示任务不存在或已失效 |
| `409` | 任务尚未成功，不能下载或编辑 | 等待任务完成后再操作 |
| `500` | 后端内部错误 | 展示错误并记录日志 |

任务失败时，状态接口中会返回：

```json
{
  "status": "failed",
  "message": "foreground mask extraction failed",
  "error": "具体错误信息"
}
```

## 16. 当前限制与注意事项

当前版本有以下限制：

- 任务状态保存在后端内存中，服务重启后历史 `task_id` 会丢失；
- 路径方式要求 `input_path` 是后端机器能够访问的路径；
- 人工编辑当前只支持删除误检前景，不支持补画漏检前景；
- 人工编辑会覆盖当前任务的最终 `mask.png` 和 `mask.tif`；
- `probability.tif` 保留模型原始输出，不会被人工编辑修改；
- 当前没有独立的鉴权、用户隔离和任务持久化机制；
- 前端通过文件路径访问输出文件时，需要确保软件集成层能读取这些路径，纯浏览器场景可能需要后端再增加静态文件服务或文件代理接口。

## 17. 前端最小联调示例

### 17.1 创建任务

```javascript
const res = await fetch("http://127.0.0.1:8000/api/preprocessing/foreground-mask", {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({
    input_path: "examples/input",
    image_pattern: "*.tif",
    model_profile: "default",
    threshold: 0.5,
    enable_postprocess: true,
    output_preview: true
  })
});

const job = await res.json();
console.log(job.task_id);
```

### 17.2 轮询状态

```javascript
async function waitForJob(taskId) {
  while (true) {
    const res = await fetch(`http://127.0.0.1:8000/api/preprocessing/status/${taskId}`);
    const task = await res.json();

    if (task.status === "succeeded") return task;
    if (task.status === "failed") throw new Error(task.error || "Mask task failed");

    await new Promise(resolve => setTimeout(resolve, 1000));
  }
}
```

### 17.3 提交人工删除区域

```javascript
async function removeMaskRegion(taskId) {
  const res = await fetch(
    `http://127.0.0.1:8000/api/preprocessing/foreground-mask/${taskId}/mask-edits`,
    {
      method: "POST",
      headers: { "Content-Type": "application/json" },
      body: JSON.stringify({
        operation: "remove",
        display_width: 1024,
        display_height: 512,
        regions: [
          {
            type: "rectangle",
            bbox: [120, 80, 260, 180]
          }
        ],
        output_preview: true
      })
    }
  );

  if (!res.ok) {
    throw new Error(await res.text());
  }

  return await res.json();
}
```

## 18. 建议的前后端职责边界

前端负责：

- 提供图像选择或任务入口；
- 展示原图、叠加图、掩膜、轮廓和质量信息；
- 提供框选、多边形、画笔等人工编辑工具；
- 将用户选择区域转换为 JSON 请求；
- 处理任务轮询、错误提示和结果刷新。

后端负责：

- 加载模型包和推理配置；
- 读取图像并执行前景掩膜提取；
- 生成二值掩膜、概率图、叠加图、轮廓和元数据；
- 接收前端人工编辑区域；
- 修改最终掩膜并刷新派生结果；
- 保证后续算法模块能够读取最新 `mask.tif`。

## 19. 后续可扩展方向

后续版本可以在当前接口基础上继续扩展：

- 增加 `operation: "add"`，支持用户补画漏检岩心区域；
- 增加撤销/重做接口；
- 增加任务持久化和历史任务查询；
- 增加静态文件访问接口，方便纯 Web 前端直接加载输出图片；
- 增加 WebSocket 或 SSE 推送任务进度；
- 增加按连通域删除功能，例如前端点击某个 component 后直接删除；
- 增加人工编辑日志导出，用于后续模型迭代训练样本分析。
