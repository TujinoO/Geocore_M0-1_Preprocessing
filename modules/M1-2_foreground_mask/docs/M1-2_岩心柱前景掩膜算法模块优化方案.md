# M1-2 岩心柱前景掩膜算法模块优化方案

## 1. 文档目标

本文档用于梳理当前岩心智能编录软件中 **M1-2 岩心柱体前景掩膜提取算法模块** 的优化方向。当前代码基础来自遥感影像语义分割与样本生产工程，已经能够完成岩心柱前景掩膜提取的基本需求，但仍存在遥感工程痕迹较重、岩心业务约束不足、训练与软件推理边界不清晰等问题。

本方案的目标不是推翻现有代码，而是在保留可用深度学习分割能力的基础上，将其整理为更符合岩心智能编录项目需求的专用算法模块。

核心原则：

- 发布前由算法团队集中完成人工样本勾画、模型训练、模型评估与模型封装。
- 发布后普通用户只调用内置模型，不参与样本筛选、标注、训练或复杂参数配置。
- 软件侧接口保持简单稳定，算法侧保留可迭代训练和模型升级能力。
- 输出结果不仅包括二值掩膜，还应服务后续 M1-3 岩心柱分割与深度标记、M2 属性识别和前端可视化。

## 2. 当前代码主要问题

当前仓库主要由两部分组成：

- `AGRS_sample_production-main`：遥感影像样本生产流程。
- `AGRS_semantic_segmentation-main`：遥感语义分割训练、预测、测试和 API 封装流程。

这些代码为当前模块提供了重要基础，但直接套用于岩心柱前景掩膜时存在以下问题。

### 2.1 遥感场景假设过重

现有流程大量依赖 GeoTIFF、GDAL、地理投影、矢量 shp、滑窗遥感预测和多波段影像处理逻辑。岩心图像虽然可能包含 TIF 或高光谱数据，但 M1-2 前景掩膜的主要任务是从岩心箱或岩心柱图像中识别岩心实体区域，本质上更接近工业视觉/图像分割任务。

需要弱化：

- 地理坐标和投影依赖；
- 遥感 shp 样本生产流程；
- 过多多波段参数暴露；
- 以 GeoTIFF 为唯一输出结果的设计。

需要强化：

- 原图像素坐标与岩心深度映射的保留；
- 岩心箱、岩心行、断芯、碎芯、木箱背景、标签纸、阴影等专用场景处理；
- 前端叠加预览和后续切片算法可直接使用的输出。

### 2.2 训练端与发布端边界不清晰

当前训练脚本中存在大量硬编码路径和全局参数，例如训练列表路径、模型保存路径、测试数据路径、模型类型、batch size、epoch 等。这适合个人实验，但不利于形成可复现、可交付、可升级的算法模块。

发布版 API 中也暴露了过多算法内部参数，例如：

- `model_path`
- `train_list_path`
- `mean`
- `std`
- `band_num`
- `num_classes`
- `target_size`
- `ignore_bandnum`

这些参数应该由模型包或算法配置统一管理，而不是由前端或普通用户传入。

### 2.3 推理输出偏单一

当前推理主要输出单波段 `.tif` 掩膜。对于岩心智能编录软件，建议同时输出：

- 二值掩膜；
- 前景概率图；
- 原图叠加预览图；
- 岩心轮廓；
- 包围盒；
- 面积比例；
- 质量检查信息；
- 模型版本与推理参数。

这些结果可以直接支撑前端展示、人工检查、M1-3 岩心柱体分割和后续属性识别。

### 2.4 岩心专用后处理不足

遥感分割通常关注地物类别的空间分布，而岩心前景掩膜有更明确的几何和业务约束：

- 岩心通常呈长条状或碎块状；
- 背景通常为木箱、卡槽、阴影、标签纸、标尺等；
- 岩心内部裂隙、小暗斑不应被错误剔除；
- 断芯之间的真实间隔不应被后处理强行连通；
- 小面积噪声应剔除；
- 结果边界应平滑，便于前端叠加和后续图斑切割。

因此需要新增岩心场景专用后处理模块。

## 3. 优化后的整体架构

建议将算法模块拆分为两条主线：

1. **离线训练流程**：供算法团队在软件发布前使用。
2. **软件内置推理流程**：供岩心智能编录软件在正式运行时调用。

### 3.1 离线训练流程

离线训练流程负责从人工样本构建到模型发布：

```text
原始岩心图像
-> 人工勾画岩心前景区域
-> 生成同尺寸二值标签
-> 样本质检
-> 按钻孔/岩心箱划分训练集、验证集、测试集
-> 切片与数据增强
-> 模型训练
-> 独立测试集评估
-> 生成模型卡与模型包
-> 进入软件发布包
```

该流程可以保留较完整的算法参数和实验配置，但必须做到配置化、可复现、可记录。

### 3.2 软件内置推理流程

软件内置推理流程面向前端和后端服务调用：

```text
输入岩心图像
-> 读取模型包配置
-> 图像标准化
-> 滑窗推理
-> 概率图融合
-> 阈值二值化
-> 岩心专用后处理
-> 输出掩膜、预览图、轮廓和元数据
```

发布端不再要求用户传入训练参数。软件只需要指定图像路径、输出目录和少量业务参数。

## 5. 样本建设与标注规范

### 5.1 样本组织方式

建议使用如下数据结构：

```text
datasets/
  core_mask/
    raw_images/
      project_a/
      project_b/

    labels/
      project_a/
      project_b/

    splits/
      train.txt
      val.txt
      test.txt

    metadata/
      image_index.csv
      label_quality.csv
```

每条样本至少记录：

- 图像路径；
- 标签路径；
- 项目名称；
- 钻孔号；
- 岩心箱号；
- 起止深度；
- 拍摄设备；
- 图像分辨率；
- 标注人；
- 标注日期；
- 是否专家复核；
- 样本复杂度标签。

### 5.2 标注对象定义

前景应包括：

- 完整岩心柱；
- 断芯；
- 碎芯；
- 岩心实体上的湿润区域；
- 岩心内部自然裂隙两侧仍属于岩心实体的区域。

背景应包括：

- 木箱；
- 卡槽；
- 标签纸；
- 标尺；
- 阴影；
- 空洞间隙；
- 箱体边框；
- 其他非岩心物体。

需要特别约定：

- 岩心内部细小裂隙不应作为背景处理；
- 断芯之间的真实空隙应保留为背景；
- 小岩屑是否作为前景需按项目要求设定面积阈值；
- 标签纸压在岩心上时，默认标签纸为背景，除非后续业务要求保留遮挡关系。

### 5.3 数据集划分原则

训练集、验证集、测试集必须按钻孔、项目或岩心箱划分，不建议随机按切片划分。

原因是同一岩心箱的相邻切片高度相似，如果随机划分，会造成训练集和测试集数据泄漏，使测试精度虚高。

推荐比例：

- 训练集：70%
- 验证集：15%
- 测试集：15%

如果数据量较小，测试集也应至少保留若干完整钻孔或完整岩心箱。

## 6. 模型训练方案

### 6.1 模型选择

建议保留两类模型：

1. **默认发布模型：CoreMask-UNet**
   - 优点：结构稳定、训练成本低、推理速度快、部署友好。
   - 用途：作为软件正式发布版本的默认模型。

2. **高精度实验模型：CoreMask-SegFormer**
   - 优点：对复杂光照、阴影、湿岩心和复杂背景更有潜力。
   - 用途：作为后续模型升级或高精度模式候选。

初期不建议同时维护过多网络结构。当前仓库中已有大量网络模型，但 M1-2 是二分类前景掩膜任务，稳定性和可维护性比模型数量更重要。

### 6.2 损失函数

建议将二分类前景掩膜任务的默认损失函数调整为：

```text
BCEWithLogitsLoss + DiceLoss
```

如边界质量要求较高，可进一步加入：

```text
Boundary Loss
```

理由：

- BCE 适合像素级二分类；
- Dice 对前景/背景面积不均衡更友好；
- Boundary Loss 可提升岩心边缘质量。

### 6.3 数据增强

岩心前景掩膜的数据增强应模拟真实拍摄变化，而不是照搬遥感增强。

推荐增强：

- 亮度变化；
- 对比度变化；
- 色温偏移；
- 轻微高斯噪声；
- 轻微模糊；
- 水平/垂直翻转；
- 小角度旋转；
- 随机裁剪；
- 阴影扰动；
- 木箱背景干扰增强。

谨慎使用：

- 大角度旋转；
- 强透视变换；
- 过强颜色扰动；
- 会改变岩心真实几何关系的增强。

### 6.4 训练配置管理

训练脚本应改为配置文件驱动，例如：

```yaml
experiment_name: core_mask_unet_v1
model:
  name: CoreMaskUNet
  input_channels: 3
  num_classes: 1

data:
  train_list: datasets/core_mask/splits/train.txt
  val_list: datasets/core_mask/splits/val.txt
  test_list: datasets/core_mask/splits/test.txt
  image_size: 512

training:
  epochs: 100
  batch_size: 8
  learning_rate: 0.001
  optimizer: AdamW
  loss: bce_dice

output:
  work_dir: E:/Experiment_data/GeoCore_Preprocessing_Runs/M1-2/core_mask_unet_v1
```

训练完成后应自动保存：

- 最优模型权重；
- 训练日志；
- 验证集指标；
- 测试集指标；
- 混淆矩阵；
- 典型成功样本；
- 典型失败样本；
- 模型卡。

## 7. 推理流程优化

### 7.1 输入支持

建议推理端支持：

- `.jpg`
- `.jpeg`
- `.png`
- `.tif`
- `.tiff`

读取后统一转换为模型需要的输入格式。对普通 RGB 图像使用常规图像读取方式，对高位深 TIF 或多波段数据保留 GDAL 读取能力。

### 7.2 滑窗推理与概率融合

当前流程偏向对每个窗口直接 `argmax` 后拼接，容易产生窗口边界接缝。

建议改为：

```text
每个窗口输出前景概率
-> 重叠区域按权重融合
-> 得到整图前景概率图
-> 根据阈值生成二值掩膜
```

融合方式可采用：

- 简单平均；
- 高斯权重融合；
- 中心区域高权重、边缘低权重融合。

这样能显著减轻滑窗边界突变。

### 7.3 发布端参数简化

发布版 API 不应要求前端传入模型内部参数。建议请求体简化为：

```json
{
  "input_path": "D:/data/core_box_001.tif",
  "output_dir": "D:/data/output",
  "model_profile": "default",
  "threshold": 0.5,
  "enable_postprocess": true,
  "output_preview": true
}
```

其中模型路径、均值方差、输入尺寸、通道数、模型类型等信息全部从模型包中的 `model_manifest.yaml` 读取。

## 8. 岩心专用后处理方案

后处理是当前模块最需要岩心化改造的部分。

### 8.1 连通域筛选

目标：

- 去除孤立噪声；
- 去除木箱纹理误检；
- 去除小面积标签纸误检；
- 保留主要岩心柱和有效碎块。

建议参数：

- `min_component_area`：最小连通域面积；
- `max_component_area_ratio`：异常大面积检查；
- `keep_top_k`：保留面积最大的若干连通域；
- `aspect_ratio_range`：用于识别典型长条岩心区域。

### 8.2 孔洞填充

目标：

- 修复岩心内部裂隙、小暗斑和局部阴影导致的漏检。

注意：

- 只填充连通域内部小孔洞；
- 不应跨越断芯之间的真实空隙；
- 孔洞面积阈值应可配置。

### 8.3 形态学闭合与边界平滑

目标：

- 修复掩膜边缘毛刺；
- 填补小裂缝；
- 提升前端叠加展示效果；
- 为后续 M1-3 图斑切片提供稳定边界。

建议使用：

- closing；
- opening；
- contour smoothing；
- small spur removal。

### 8.4 几何质量检查

每张图输出质量信息：

- 前景面积比例；
- 连通域数量；
- 最大连通域面积；
- 掩膜外接框；
- 是否存在异常过大/过小前景；
- 是否存在过多碎片；
- 是否可能整图失败。

如果质量异常，接口不一定失败，但应返回 warning，供软件前端或日志系统提示。

## 9. 输出结果规范

建议每个任务输出如下文件：

```text
outputs/{task_id}/
  mask.png
  mask.tif
  probability.tif
  overlay.png
  contours.json
  metadata.json
```

### 9.1 mask.png

用于前端快速预览，取值：

- 背景：0
- 前景：255

### 9.2 mask.tif

用于后续算法流程，保持与原图同尺寸。

如原图包含地理或空间参考信息，可尽量保留；如果只是普通岩心照片，则不强制要求地理信息。

### 9.3 probability.tif

可选输出，保存前景概率图，取值范围建议为 0-1 或 0-255。

用途：

- 失败样本分析；
- 阈值调优；
- 模型验收；
- 后续质量检查。

### 9.4 overlay.png

原图与掩膜半透明叠加，用于前端展示和人工快速验收。

### 9.5 contours.json

建议结构：

```json
{
  "image_width": 4096,
  "image_height": 2048,
  "components": [
    {
      "component_id": 1,
      "area": 123456,
      "bbox": [100, 220, 1600, 420],
      "contour": [[100, 220], [101, 220]]
    }
  ]
}
```

### 9.6 metadata.json

建议结构：

```json
{
  "module": "M1-2 foreground mask",
  "model_name": "CoreMask-UNet",
  "model_version": "v1.0.0",
  "input_path": "D:/data/core_box_001.tif",
  "threshold": 0.5,
  "postprocess": true,
  "image_width": 4096,
  "image_height": 2048,
  "foreground_area_ratio": 0.32,
  "component_count": 8,
  "warnings": [],
  "elapsed_seconds": 2.31
}
```

## 11. 模型包设计

建议将发布模型封装为独立模型包：

```text
models/
  core_mask_unet_v1/
    weights.pth
    model_manifest.yaml
    metrics.json
    model_card.md
```

### 11.1 model_manifest.yaml

示例：

```yaml
model_name: CoreMask-UNet
model_version: v1.0.0
task: M1-2 foreground mask
framework: pytorch
weights: weights.pth

input:
  channels: 3
  image_size: 512
  mean: [123.4, 117.2, 105.8]
  std: [52.1, 49.8, 48.7]

inference:
  threshold: 0.5
  tile_size: 512
  overlap: 0.25
  device: auto

postprocess:
  enable: true
  min_component_area: 100
  fill_hole_area: 500
  smooth_kernel_size: 5
```

### 11.2 model_card.md

模型卡应记录：

- 训练数据来源；
- 样本数量；
- 标注规范；
- 训练集/验证集/测试集划分方式；
- 模型结构；
- 训练参数；
- 验收指标；
- 典型成功场景；
- 典型失败场景；
- 不适用场景；
- 模型版本变更记录。

## 12. 评估指标与验收标准

建议 M1-2 独立形成模型验收报告。

核心指标：

- Dice；
- IoU；
- Precision；
- Recall；
- Boundary IoU；
- 前景面积误差；
- 连通域数量误差；
- 单图平均推理耗时。

建议验收目标：

```text
Dice >= 0.95
IoU >= 0.90
Boundary IoU >= 0.88 或 0.90
前景面积误差 <= 3%-5%
```

必须覆盖的复杂样本类型：

- 湿岩心；
- 暗色岩心；
- 浅色岩心；
- 破碎岩心；
- 强阴影；
- 木箱纹理干扰；
- 标签纸干扰；
- 断芯缺失；
- 背景颜色接近岩心的样本。

## 14. 结论

当前算法模块已经具备可运行的深度学习分割基础，但仍更像遥感语义分割工程的迁移版本。后续优化重点应放在：

- 训练流程配置化；
- 发布端推理简化；
- 岩心专用后处理；
- 输出结果结构化；
- 模型包和模型卡规范化；
- API 面向业务而不是面向训练参数。

按照本方案整理后，M1-2 模块可以从“能跑的遥感迁移代码”升级为“可发布、可验收、可复用、可持续升级的岩心柱前景掩膜算法模块”。
