# M0&1 工程链路核查（2026-09-28）

## 结论

源码已包含 M0 影像融合 → M1_1 岩心箱检测/旋转 → M1_2 V4 前景掩膜 → M1_3 按箱槽数分柱、重组与图斑输出的调用链。真实 ZKZ4-5 橙色扫描的 **15 箱均已完成原生分辨率 M1_1、V4 掩膜、自动判槽及保留空隙版 M1_3 长条/图斑 QA**。但标签误检、50 处待核空隙、真实深度方向未核实，以及全幅 M0 容量限制仍在，**不能宣称跨场景、像素级完美分割或正式深度成果已验收**。

## 本次修正

1. M1_1 对多 GB ENVI 扫描先抽样再生成缩略图；按 HDR 的 `default bands={2,1,0}` 还原 RGB；橙色箱依据上下横梁配对，扩展到外框并限制相邻框不重叠；角度估计和人工复核源图使用有界抽样，人工框选坐标由后端映回原图，校正仍写全分辨率。
   首次整批 QA 用灰度裂隙估计残余倾角，误报 6 箱；保留在 `qa_gray_legacy_false_positive.json`。改为橙色竖框证据后，15 箱均通过 0.2° 门槛。灰度误报和重新评估均未当作独立验证。
2. 统一入口优先使用原始 RGB，而非可能缩小的 M0 预览；缺少原图时拒绝用缩略图冒充原始尺度。
3. M1_3 默认自动识别槽数，低置信度或指定槽数冲突即停止；分界落在槽间空隙，消除相邻槽像素重叠；对可靠橙色上下横梁清除前景误检。
4. 大图读取限定 Pillow 最大像素数为 3 亿；长条 JPEG 预览缩至 4096 px 高并正确使用 alpha，完整 PNG 不降采样。
5. 缺失总深度时拒绝生成虚构深度；未提供逐箱深度时标记等分估计；未核实左右/上下顺序时标记 `depth_order_unverified`。统一结果将 M1_1 人工复核标记、M1_2 模型警告和 M1_3 警告汇入 `box_review_items`，有任一待核项时 `quality_status=needs_review`，不冒充自动验收。
6. M0 运行前按实际 Zarr 边界块尺寸估算磁盘占用，大幅面超出可用空间或未开启流式时提前停止；这只是安全门，尚未实现整幅扫描的按需/紧凑融合存储。
7. M1_3 独立 API 原先默认强制 5 槽，与统一入口和模块核心的自动判槽不一致；现默认 `lane_count=0`，在低置信或配置冲突时继续拒绝分槽。
8. M1_2 原轮廓导出对每个连通域重复扫描约 2 亿像素全图，稀碎岩心箱严重超时；现仅在连通域局部边界框求轮廓，保持全图坐标，并加入边缘连通域回归。`box_0009` 修复后完整推理 25.97 秒，含 647 个连通域。
9. M1_3 旧默认 `close_artificial_gaps` 在 15 箱 QA 中压缩了 50 处大空隙，可能改变缺失岩心对应关系；现默认 `preserve_all_gaps` 并对大空隙继续告警。人工确认是摆放空白后，仍可显式选择压缩。新旧成果分目录保留，安全版各箱长条比旧版多 40–2015 px。
