## 人工标注怎样进入 M1_3

1. `tools/build_source_slot_priors.py` 从 SHP 审计结果生成 `source_slot_priors_v2.json`：4 条原始影像有至少两个同槽数标注箱，可提供**来源级槽数先验**；其中 3 条还具有稳定的归一化隔板位置。单箱来源或编号不完整的隔板几何不自动放行。该先验只会在综合流程中标记槽数冲突，不会替代逐箱真值。
2. 综合 CLI 新增 `--source-slot-priors-json`。若当前箱的自动槽数与同来源人工标注箱不一致，`review_manifest.json` 写 `source_slot_count_prior_disagreement`。没有逐箱确认隔板时写 `physical_slot_count_unverified`，并将 `physical_slot_count_verified=false` 送入结果。不会静默把错误槽数写成已验证。
3. 若已有某次 M1_1 运行的 `metadata.json` 和校正影像，`tools/export_shp_dividers_for_m11.py` 可以把**同一次运行、同一个原始 ENVI 影像**的 SHP 槽位，通过旋转矩阵与裁剪偏移，转为 `box_XXXX -> [x1,x2,…]` 的校正图像像素坐标。仅导出箱界 IoU ≥ 0.75、`SLOT_IDX` 完整、坐标有效且校正后隔板纵向漂移不过大的已标注箱；同时生成 `_qa.json`。该映射可交给综合 CLI 的 `--lane-dividers-by-box-json`，但不得挪用于别次 M1_1 运行或未标注箱。
   如果同一 `.dat` 存在两份不同路径的副本，可显式加 `--allow-identical-source-copies`；脚本必须先确认 `.hdr` 相同且完整 `.dat` SHA-256 相同才导出，数据较大时需等待读取完成。

已用 `RGB-20230910_090147-00000.dat` 做实际校正回归：M1_1 输出 5 箱，`sample_001` 匹配 `box_0002`，成功得到 5 条校正图像隔板线 `[482, 659, 834, 1012, 1188]`；叠加图中这些线位于相邻物理槽间。该检查只证明这一箱的 SHP 坐标转换可用，不代表其它 15 箱或跨场景自动分槽已验证。

另用仅供坐标单测的恒等/抽样步长变换检查 16 个正样本：15 个可生成按序隔板，`sample_005` 因 `SLOT_IDX=0` 被明确拒绝。恒等变换检查不是实际 M1_1 校正回归。

对历史 ZKZ4-5 橙色 15 箱运行，已用完整 `.dat` SHA-256 与相同 `.hdr` 验证标注副本和校正输入为同一数据，再将 `sample_011/012/013` 分别映射到 `box_0003/0008/0012`，得到两条逐箱隔板。三箱的原生 V4 掩膜均自动估计为 3 槽，人工隔板输入 `detect_lanes` 后也各保留 3 条槽；自动隔板与人工位置的最大差为 76 像素（图宽约 7420–7999 像素）。这只是已标注的橙色 3 槽场景回归，不外推到五/六槽暗色箱。
